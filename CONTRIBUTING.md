# Contributing

This is a Markdown profile, not an application. Read [CODE_OF_CONDUCT.md](CODE_OF_CONDUCT.md)
and use [SECURITY.md](SECURITY.md) for private concerns.

## Preview and validation

Edit `README.md` in a Markdown editor or GitHub's preview. Check headings,
rendered links, the collapsed repository-details section, and mobile readability.
Run `git diff --check`. No dependencies, environment variables, or unit-test
suite are needed for the current content. Automated content checks are planned.

## Content changes

Keep the introduction concise. Link to each project's current README for
changing metrics and runtime details. If adding a numerical public-project
claim, record its date, definition, and source. Confirm changes to private-work
and employment claims with the maintainer. Public code cannot independently
verify those claims, and an editor should not invent supporting evidence.

Use a focused PR and describe how the rendered result and links were checked.
Record meaningful changes in [CHANGELOG.md](CHANGELOG.md). Avoid em and en dashes
in new text and commit messages. Link unfinished work with a TODO and issue.
See [docs/maintenance.md](docs/maintenance.md) for branch-policy recommendations.
